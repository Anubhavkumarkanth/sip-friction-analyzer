2. What is SIP Friction Analyzer?

The Problem It Solves

Most individual investors fail to maintain discipline in their Systematic Investment Plans (SIPs). During market downturns, they pause contributions, reduce amounts, or skip months. These actions create "friction" that compounds negatively over years, resulting in substantial wealth loss that many investors never quantify or understand.

Key Insight: An investor with perfect discipline earning 12% annual return accumulating ₹48 lakhs over 20 years may only achieve ₹39 lakhs if they pause their SIP for 12 months during a market crash. That is a loss of ₹9 lakhs—nearly 19% of potential wealth—all because of one year of pausing.

The Solution

SIP Friction Analyzer provides an interactive tool where investors can:

  1. Specify their monthly investment amount
  2. Input their expected annual return percentage
  3. Define their investment period (years)
  4. Add "friction events" (pause SIP, reduce contribution, skip months)
  5. See side-by-side comparison: ideal wealth vs. actual wealth with friction
  6. Understand the financial cost of indiscipline through visualizations and metrics

The Output

The application generates:

Output Element What It Shows Purpose
Interactive Area Chart Blue line (ideal) vs Red line (actual) vs Grey area (loss) Visual understanding of friction impact over time
Ideal Wealth Money accumulated with perfect discipline Benchmark for comparison
Actual Wealth Money accumulated with friction events Realistic outcome
Compounding Loss Absolute ₹ amount lost due to friction Quantifies financial impact
CCR (Contribution Compliance Rate) Percentage of planned contributions actually made Measures discipline level
Discipline Score 0-100 score combining CCR and compounding loss Holistic discipline metric

4. Simulation Engine - engine/simulation.py

Purpose: Contains SIPSimulator class with core financial calculations.

SIP (Systematic Investment Plan): A method of investing a fixed amount of money in mutual funds at regular intervals (monthly, quarterly, etc.). Formula: Future Value = P × {[(1 + r)^n - 1] / r} × (1 + r) Where: P = monthly amount, r = monthly return, n = number of months

5. Metrics Engine - engine/friction.py

Purpose: Calculates financial metrics that measure investor discipline.

Three Key Metrics:

1. CCR (Contribution Compliance Rate)
  • Formula: Total Actual Contributions / Total Expected Contributions
  • Range: 0 to 1 (0% to 100%)
  • Example: If you planned ₹2.4L (12 months × ₹20K) but only contributed ₹2.1L, CCR = 87.5%
  • Interpretation: How much of planned investment was actually made
2. CLD (Compounding Loss Difference)
  • Formula: Ideal Wealth - Actual Wealth
  • Range: 0 to Ideal Amount
  • Example: If ideal is ₹48L but actual is ₹39L, CLD = ₹9L
  • Interpretation: Absolute rupee amount lost due to friction
3. Discipline Score
  • Formula: 100 - (40 × (1 - CCR) + 60 × (CLD / Ideal))
  • Range: 0 to 100
  • Weighting: 40% from contribution compliance, 60% from compounding impact
  • Interpretation: Overall discipline score; higher is better
  • Colored: Green (≥90), Yellow (60-90), Red (<60)

The runSimulation() Function - Core Logic

This is the heart of the application. Here's how it works:

Step-by-Step Simulation Process: 1. Parse Inputs
Monthly Amount: 10,000 → parseFloat() → 10000 Annual Return: 12 → parseFloat() → 12 Years: 20 → parseFloat() → 20
2. Setup Loop Variables
monthlyReturn = 12% / 12 = 1% per month = 0.01 totalMonths = 20 × 12 = 240 months idealValue = 0 actualValue = 0
3. Run 240 Iterations (one per month)
FOR month = 1 TO 240: a) Ideal: idealValue = (idealValue + 10000) × (1 + 0.01) b) Actual: - Start with contribution = 10000 - Check pause ranges (if month in range, contribution = 0) - Check friction events (reduce, skip, increase) - Apply: actualValue = (actualValue + contribution) × (1 + 0.01) c) Every 12 months: Record data point for chart END FOR
4. Calculate Metrics
cld = idealValue - actualValue ccr = totalActual / totalExpected discipline_score = 100 - (40×(1-ccr) + 60×(cld/ideal))
5. Generate Chart Data
chartData = [ { year: 1, ideal: 127,500, actual: 125,000, difference: 2,500 }, { year: 2, ideal: 265,250, actual: 258,750, difference: 6,500 }, ... { year: 20, ideal: 48,24,567, actual: 39,18,420, difference: 9,06,147 } ]

9. Key Features Explained in Detail

Feature 1: SIP Simulation Engine

Feature: Month-by-month wealth accumulation calculator that shows the impact of investment discipline on compound growth.

How It Works:

  1. User inputs: monthly amount, annual return %, investment years
  2. System calculates two scenarios:
    • Ideal: Perfect discipline every month
    • Actual: With friction events (pauses, reduces, skips)
  3. Compares month-by-month values for 240 months (20 years)
  4. Generates 20 annual data points for visualization
  5. Calculates three metrics: CCR, CLD, Discipline Score

Mathematical Formula Used:

For each month: IdealValue(month) = (IdealValue(month-1) + MonthlyAmount) × (1 + MonthlyReturn) ActualValue(month) = (ActualValue(month-1) + AdjustedContribution) × (1 + MonthlyReturn) Where: MonthlyReturn = AnnualReturn / 12 / 100 AdjustedContribution = MonthlyAmount (or 0 if paused, or × factor if reduced) Example with 12% annual return: MonthlyReturn = 12 / 12 / 100 = 0.01 (1% per month) Month 1: (0 + 10000) × 1.01 = 10,100 Month 2: (10100 + 10000) × 1.01 = 20,301 Month 3: (20301 + 10000) × 1.01 = 30,604.01

Feature 2: Friction Events System

What are Friction Events?

Event Type What It Does User Input Impact
PAUSE_RANGE Stop contributing for months X-Y Start month, End month Contribution = 0 in range
STEP_UP Increase monthly amount by % annually Annual increase % Monthly amount × (1 + %)
REDUCE Reduce to X% of original at month Y Month, Factor (0.5 = 50%) 10000 × 0.5 = 5000
SKIP Skip contribution at specific month Month Contribution = 0 for that month
INCREASE Increase to X% of original at month Y Month, Factor (1.5 = 150%) 10000 × 1.5 = 15000

Real-World Scenario:

Investor Profile: Rahul starts SIP in Jan 2024 with ₹10,000/month at 12% return What Actually Happened: - Months 1-40: Perfect discipline - Month 41-45 (April-Aug 2027): Market crash, pauses SIP - Month 46-240 (Sept 2027-Aug 2046): Resumes but reduces to ₹8,000/month Simulation Result: - Ideal (perfect discipline): ₹48.25 Lakhs - Actual (with events): ₹42.10 Lakhs - Loss: ₹6.15 Lakhs (12.7% of potential wealth) - Discipline Score: 78/100 Learning: Even after resuming the SIP, the 5-month pause costs 12.7% of wealth over 20 years!

Feature 5: Monte Carlo Simulation

What It Does: Runs 1,000+ simulations with market volatility included

Monte Carlo Simulation: A statistical technique that runs the same calculation thousands of times with different random market conditions (volatility) to show the range of possible outcomes and their probabilities.

Why It Matters:

  • Single simulation assumes fixed 12% return every year
  • Real markets: Some years 20%, some years 5%, some years -10%
  • Monte Carlo shows what could happen accounting for this randomness
  • Output: 10th, 50th, 90th percentile outcomes

Why SQLite?

SQLite vs PostgreSQL vs MySQL:

  • PostgreSQL: Powerful server, for production with 1000+ users
  • MySQL: Server-based like PostgreSQL, similar complexity

Our Project: Single developer, <100 potential users → SQLite is ideal. Switching to PostgreSQL takes 2 hours if we hit limits later.

Code Organization Decisions

Why Service Layer (api.ts)?

Without Service Layer (API calls everywhere):

// Dashboard.jsx const funds = await axios.get('/search-funds?q=' + query) // FundExplorer.jsx const funds = await axios.get('/search-funds?q=' + query) // CompareFunds.jsx const funds = await axios.get('/search-funds?q=' + query) Problem: Change /search-funds URL → Change 3 files!

With Service Layer (centralized):

// services/api.ts - ONE place export const fundsAPI = { search: (query) => axios.get(`/search-funds?q=${query}`) } // Dashboard.jsx const funds = await fundsAPI.search(query) // FundExplorer.jsx const funds = await fundsAPI.search(query) // CompareFunds.jsx const funds = await fundsAPI.search(query) Benefit: Change URL in 1 place, everywhere updates automatically!

Why Custom Hooks (useForm, useFetch)?

Without Hooks (Code Duplication):

// Every component doing this const [loading, setLoading] = useState(false) const [error, setError] = useState(null) const [data, setData] = useState(null) useEffect(() => { setLoading(true) fetchData() .then(data => setData(data)) .catch(err => setError(err)) .finally(() => setLoading(false)) }, [deps]) // Repeated in Dashboard, FundExplorer, CompareFunds...

With Custom Hooks (DRY Principle):

// ONE hook export const useFetch = (fetchFn, deps) => { const [state, setState] = useState({data: null, loading: true, error: null}) useEffect(() => { /* handle fetch */ }, deps) return state } // Used everywhere const { data, loading, error } = useFetch(() => api.getFunds(), []) // DRY: Don't Repeat Yourself!

Question 3: "Walk me through the SIP calculation logic"
