2. What is SIP Friction Analyzer?

The Problem It Solves

Most individual investors fail to maintain discipline in their Systematic Investment Plans (SIPs). During market downturns, they pause contributions, reduce amounts, or skip months. These actions create "friction" that compounds negatively over years, resulting in substantial wealth loss that many investors never quantify or understand.

Key Insight: An investor with perfect discipline earning 12% annual return accumulating ₹48 lakhs over 20 years may only achieve ₹39 lakhs if they pause their SIP for 12 months during a market crash. That is a loss of ₹9 lakhs—nearly 19% of potential wealth—all because of one year of pausing.

The Solution

SIP Friction Analyzer provides an interactive tool where investors can:

  1. Specify their monthly investment amount
  2. Input their expected annual return percentage
  3. Define their investment period (years)
  4. Add "friction events" (pause SIP, reduce contribution, skip months)
  5. See side-by-side comparison: ideal wealth vs. actual wealth with friction
  6. Understand the financial cost of indiscipline through visualizations and metrics

The Output

The application generates:

Output Element What It Shows Purpose
Interactive Area Chart Blue line (ideal) vs Red line (actual) vs Grey area (loss) Visual understanding of friction impact over time
Ideal Wealth Money accumulated with perfect discipline Benchmark for comparison
Actual Wealth Money accumulated with friction events Realistic outcome
Compounding Loss Absolute ₹ amount lost due to friction Quantifies financial impact
CCR (Contribution Compliance Rate) Percentage of planned contributions actually made Measures discipline level
Discipline Score 0-100 score combining CCR and compounding loss Holistic discipline metric

4. Simulation Engine - engine/simulation.py

Purpose: Contains SIPSimulator class with core financial calculations.

SIP (Systematic Investment Plan): A method of investing a fixed amount of money in mutual funds at regular intervals (monthly, quarterly, etc.). Formula: Future Value = P × {[(1 + r)^n - 1] / r} × (1 + r) Where: P = monthly amount, r = monthly return, n = number of months

SIPSimulator Class Methods:

Method Input Output Purpose
calculate_ideal() None (uses constructor params) List of monthly values Calculates wealth with perfect discipline
calculate_actual(events) List of friction events List of monthly values Calculates wealth with friction events
monte_carlo(events, simulations) Events, simulation count Distribution of outcomes Runs 1000+ iterations with market volatility

5. Metrics Engine - engine/friction.py

Purpose: Calculates financial metrics that measure investor discipline.

Three Key Metrics:

1. CCR (Contribution Compliance Rate)
  • Formula: Total Actual Contributions / Total Expected Contributions
  • Range: 0 to 1 (0% to 100%)
  • Example: If you planned ₹2.4L (12 months × ₹20K) but only contributed ₹2.1L, CCR = 87.5%
  • Interpretation: How much of planned investment was actually made
2. CLD (Compounding Loss Difference)
  • Formula: Ideal Wealth - Actual Wealth
  • Range: 0 to Ideal Amount
  • Example: If ideal is ₹48L but actual is ₹39L, CLD = ₹9L
  • Interpretation: Absolute rupee amount lost due to friction
3. Discipline Score
  • Formula: 100 - (40 × (1 - CCR) + 60 × (CLD / Ideal))
  • Range: 0 to 100
  • Weighting: 40% from contribution compliance, 60% from compounding impact
  • Interpretation: Overall discipline score; higher is better
  • Colored: Green (≥90), Yellow (60-90), Red (<60)

The runSimulation() Function - Core Logic

This is the heart of the application. Here's how it works:

Step-by-Step Simulation Process: 1. Parse Inputs
Monthly Amount: 10,000 → parseFloat() → 10000 Annual Return: 12 → parseFloat() → 12 Years: 20 → parseFloat() → 20
2. Setup Loop Variables
monthlyReturn = 12% / 12 = 1% per month = 0.01 totalMonths = 20 × 12 = 240 months idealValue = 0 actualValue = 0
3. Run 240 Iterations (one per month)
FOR month = 1 TO 240: a) Ideal: idealValue = (idealValue + 10000) × (1 + 0.01) b) Actual: - Start with contribution = 10000 - Check pause ranges (if month in range, contribution = 0) - Check friction events (reduce, skip, increase) - Apply: actualValue = (actualValue + contribution) × (1 + 0.01) c) Every 12 months: Record data point for chart END FOR
4. Calculate Metrics
cld = idealValue - actualValue ccr = totalActual / totalExpected discipline_score = 100 - (40×(1-ccr) + 60×(cld/ideal))
5. Generate Chart Data
chartData = [ { year: 1, ideal: 127,500, actual: 125,000, difference: 2,500 }, { year: 2, ideal: 265,250, actual: 258,750, difference: 6,500 }, ... { year: 20, ideal: 48,24,567, actual: 39,18,420, difference: 9,06,147 } ]

7. API Endpoints & Data Flow

What is an API Endpoint?

API Endpoint: A specific URL on the server that accepts requests (from frontend) and returns data (to frontend). Think of it as a mailbox: frontend sends a letter with specific request, server reads it and sends back appropriate response. Anatomy: METHOD /path - METHOD: GET (read), POST (create/calculate), PUT (update), DELETE (remove) - /path: Where to send request (e.g., /simulate, /search-funds)

Complete API Endpoints

Data Flow: Complete Request-Response Cycle

USER ACTION: User clicks "Run Simulation" STEP 1: Frontend Validates ├─ Check monthly_amount > 0 ├─ Check annual_return in 0-30% ├─ Check years in 1-50 └─ If invalid: Show error, stop STEP 2: Frontend Prepares Request ├─ Collect input values ├─ Build request object └─ Add any friction events STEP 3: Frontend Sends HTTP Request └─ POST http://localhost:8000/simulate with JSON body containing params STEP 4: Backend Receives Request ├─ Parse request JSON ├─ Validate types (Pydantic) └─ Extract fields STEP 5: Backend Calculates ├─ Create SIPSimulator instance ├─ Run 240 month loops ├─ Apply friction events ├─ Calculate metrics └─ Create results object STEP 6: Backend Returns Response └─ Convert results to JSON Send HTTP 200 with data STEP 7: Frontend Receives Response ├─ Parse response JSON ├─ Store in state └─ Update UI STEP 8: UI Renders Results ├─ Chart renders with data ├─ Stat cards display metrics ├─ CCR bar shows compliance └─ User sees visualization STEP 9: User Understands Impact └─ Sees ₹ loss due to friction Learns importance of discipline
